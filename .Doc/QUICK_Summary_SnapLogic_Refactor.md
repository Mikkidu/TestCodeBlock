# 🎯 Краткая справка: Переписана логика выбора snap точек

**Дата:** 2026-01-14
**Статус:** ✓ Реализовано и скомпилировано

---

## Что изменилось

### Было (Приоритизированный выбор)
```
FindNearestOutput()    ← Priority 1 (конец цепи) / Priority 2 (середина)
FindNearestInput()     ← Priority 1 (без входящих) / Priority 2 (с входящими)
                       + Гистерезис (priorityThreshold = 25px)

Проблема: "Липкость" - если Priority 1 был ближе, остаемся на нём до -25px
```

### Стало (Геометрический выбор)
```
FindNearestSnap()      ← Считаем ОБА расстояния одновременно
                       ← Выбираем ближайший (без приоритизации)
                       ← INPUT→OUTPUT на равенстве

Преимущество: Всегда выбирается геометрически ближайший снеп
```

---

## Новая логика в 3 шага

**Шаг 1:** Расстояния INPUT → OUTPUT (все блоки)
```
INPUT перетаскиваемого — все OUTPUT всех блоков
→ nearestInputToOutputDist
```

**Шаг 2:** Расстояния OUTPUT → INPUT (только блоки БЕЗ входящих)
```
OUTPUT перетаскиваемого — INPUT блоков без входящих соединений
→ nearestOutputToInputDist
```

**Шаг 3:** ВЫБИРАЕМ БЛИЖАЙШИЙ
```
Если INPUT→OUTPUT < OUTPUT→INPUT  → INPUT→OUTPUT
Если OUTPUT→INPUT < INPUT→OUTPUT  → OUTPUT→INPUT
Если равны                         → INPUT→OUTPUT (приоритет)
Если оба не найдены                → Нет snap'а
```

---

## Результат на скриншоте

```
Было:  красный блок выше последнего → магнитится к последнему ❌
Стало: красный блок выше последнего → магнитится к предпоследнему ✓
```

**Почему:**
- Было: Priority 1 = конец цепи (последний) был "липким"
- Стало: Расстояние до предпоследнего OUTPUT ближе, вот и выбирается

---

## Коды в console

```
[SNAP CHOICE] INPUT→OUTPUT closer (10.5px < 20.3px) → Block_2
```

Показывает:
- Тип выбранного snap'а
- Расстояния обоих вариантов
- Целевой блок
