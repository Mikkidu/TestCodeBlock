## Что было изменено

### 1. SnapManager.cs - Основные изменения

#### A. FindNearestOutput() - переделана с приоритизацией

**Было:**
- Поиск просто ближайшего OUTPUT по расстоянию
- Без учёта позиции блока в цепи

**Стало:**
- Двухуровневая приоритизация:
  - **Приоритет 1:** OUTPUT блоков в конце цепи (output.connectedTo == null)
  - **Приоритет 2:** OUTPUT блоков в середине цепи (output.connectedTo != null)
- Сначала ищет среди Приоритета 1, затем Приоритета 2
- Внутри одного приоритета выбирает ближайший по расстоянию

**Строки кода:** 26-138 (была 27-96)
**Добавлено:** ~110 строк кода для приоритизации и документации

#### B. FindNearestInput() - переделана с приоритизацией

**Было:**
- Поиск просто ближайшего INPUT по расстоянию
- Без различия между начальными и промежуточными блоками цепи

**Стало:**
- Двухуровневая приоритизация:
  - **Приоритет 1:** INPUT блоков без входящей связи (начало цепей)
  - **Приоритет 2:** INPUT блоков с входящей связью (для вставки в середину)
- Сначала ищет среди Приоритета 1, затем Приоритета 2
- Внутри одного приоритета выбирает ближайший по расстоянию

**Строки кода:** 140-252 (была 99-168)
**Добавлено:** ~110 строк кода для приоритизации и документации

#### C. HasIncomingConnection() - новый вспомогательный метод

**Назначение:** Проверить есть ли входящее соединение (какой-то OUTPUT подключен к данному INPUT)

**Код:**
```csharp
private bool HasIncomingConnection(BlockConnector targetInput, List<BlockUI> allBlocks)
```

**Использование:** В FindNearestInput() для определения приоритета блока

**Строки кода:** 254-272
**Размер:** ~18 строк кода

## Технические детали

### Алгоритм поиска с приоритизацией

```
Поиск OUTPUT для INPUT (FindNearestOutput):
├─ Разделить OUTPUT на две группы:
│  ├─ Группа 1: output.connectedTo == null (конец цепи)
│  └─ Группа 2: output.connectedTo != null (середина цепи)
├─ Найти ближайший в каждой группе
└─ Вернуть: сначала из Группы 1, затем из Группы 2

Поиск INPUT для OUTPUT (FindNearestInput):
├─ Разделить INPUT на две группы:
│  ├─ Группа 1: HasIncomingConnection() == false (начало цепи)
│  └─ Группа 2: HasIncomingConnection() == true (середина цепи)
├─ Найти ближайший в каждой группе
└─ Вернуть: сначала из Группы 1, затем из Группы 2
```

### Сложность

- **Временная сложность:** O(N×M) где N = количество блоков, M = среднее количество коннекторов
- **Пространственная сложность:** O(1) - только локальные переменные
- **Оптимизация:** Ранний выход при нахождении Приоритета 1

## Примеры работы

### До реализации (проблема)

```
Цепь:  [A] → [B] → [C]

Пользователь хочет добавить блок в конец (к C):
1. Берёт блок X за INPUT
2. Приносит к OUTPUT C и OUTPUT B одновременно
3. Система выбирает ближайший - часто это B (середина)!
4. Блок вставляется между B и C: A → B → X → C
5. Не то, что хотел пользователь!
```

### После реализации (решение)

```
Цепь:  [A] → [B] → [C]

Пользователь хочет добавить блок в конец (к C):
1. Берёт блок X за INPUT
2. Приносит к OUTPUT C и OUTPUT B одновременно
3. Система видит: OUTPUT C имеет Приоритет 1 (конец), OUTPUT B имеет Приоритет 2 (середина)
4. Система выбирает OUTPUT C (Приоритет 1)
5. Блок встаёт в конец: A → B → C → X
6. Ровно то, что хотел пользователь! ✓
```

✓ **Проблема 1:** Магнитное притяжение не учитывает позицию в цепи

✓ **Проблема 3:** Нет информации о том как определить начало/конец цепи
✓ **Решение:** Добавлен метод HasIncomingConnection() для проверки входящих соединений
