# #10 Двусторонний снап (вставка блоков в начало и середину цепи)

## Goal
Реализовать снап выхода перетаскиваемого блока ко входу существующего блока. Это позволит вставлять блоки не только в конец цепи, но и в начало и в любую середину.

**Сценарий:**
- Есть цепь: Block A → Block B
- Пользователь берет Block C, подносит его выход близко к входу Block A
- Block C snap'ится к A, цепь становится: Block C → Block A → Block B

## Context
- SnapManager уже имеет FindNearestOutput (ищет ближайший OUTPUT для INPUT перетаскиваемого блока)
- Нужно добавить FindNearestInput (ищет ближайший INPUT для OUTPUT перетаскиваемого блока)
- Нужно переконектить соединения при snap: старая связь A→B должна стать C→B, и A подключить к C

## Key Steps

1. **Добавить FindNearestInput в SnapManager**
   - Найти ближайший INPUT точку среди всех существующих блоков
   - Проверить расстояние против snapDistance
   - Вернуть SnapInfo с информацией о целевом INPUT

2. **Реализовать переподключение при snap выхода к входу**
   - Когда OUTPUT snap'ится к INPUT существующего блока:
     - Найти, какой OUTPUT был подключен к этому INPUT
     - Переподключить этот OUTPUT к OUTPUT перетаскиваемого блока (вставка в цепь)
     - Подключить новую связь: OUTPUT перетаскиваемого → старый INPUT

3. **Объединить две логики snap в OnDrop**
   - Сначала проверить FindNearestInput (снап выхода)
   - Если не сработал, проверить FindNearestOutput (снап входа) - как было до этого
   - Применить соответствующий snap

4. **Обновить визуальный feedback**
   - При близости OUTPUT к INPUT: подсветить TARGET INPUT желтым
   - При близости INPUT к OUTPUT: подсветить TARGET OUTPUT желтым (как было)
   - Четкая визуализация какой тип snap может произойти

5. **Тестирование**
   - Вставить блок в начало цепи (выход → вход первого блока)
   - Вставить блок в середину цепи (выход → вход среднего блока)
   - Убедиться что цепь переконектилась правильно и выполняется в корректном порядке

## Acceptance Criteria
- [ ] FindNearestInput находит ближайший INPUT на нужном расстоянии
- [ ] ApplySnapToInput переконектит соединения правильно
- [ ] OnDrop проверяет обе логики snap (INPUT и OUTPUT)
- [ ] Визуальный feedback отличает два типа snap
- [ ] Цепь выполняется в правильном порядке при вставке блока в начало/середину
- [ ] Debug логи показывают переконектившиеся соединения

## Blockers & Risks
- Нужно быть осторожным с переконектированием - неправильная логика может нарушить цепь
- Тестирование с несколькими блоками в цепи

## Notes
- Можно сначала реализовать для одного OUTPUT (как сейчас), потом расширить на несколько
- Можно добавить визуальный preview того как изменится цепь при snap'е
